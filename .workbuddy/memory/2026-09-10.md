### 关键发现（下次继续做必须知道）

1. **这个 Dify fork 的 DAG 引擎不在仓库里**，而在第三方库 `graphon`（`api/.venv/.../graphon`）。
   `core/workflow/` 只剩 Dify 特有节点与适配层；引擎（GraphEngine/VariablePool/BuiltinNodeTypes）
   与内置节点（llm/code/template-transform/if-else/iteration/loop/tool/...）全在 graphon 里。
   → Java 版需自己实现引擎，我已在 `jify-engine` 移植了核心。
2. **Spring Boot 4 默认 Jackson 3**（`tools.jackson.*`），不是 Jackson 2。
   `ObjectMapper.builder()` 不存在（builder 在 `JsonMapper`），要用 `new ObjectMapper()`。
   所有 JSON 读写统一收敛在 `jify-common` 的 `JsonUtils`，避免 API 扩散。
3. **Spring AI 2 的 `Usage.getTotalTokens()` 返回 `Integer` 不是 `Long`**。
4. `model_runtime` 不需要移植——Spring AI 2 的 ChatModel/EmbeddingModel 正是同一层抽象，已用 `LlmService` 薄封装替代。
5. 引擎曾出现**挂死**：完成判定写在 `finally` 之前，`running` 未递减导致条件永不成立、迭代器死等。
   已改为「finally 先 `running--` 再 `checkCompletion()`」，并加不可达节点兜底判失败（避免无限等待）。

### jify 第五批补全（2026-09-10 夜，human-input 暂停/恢复）

用户要求实现「运行暂停/恢复（human-input 相关）」。核心是让引擎能在 human-input 节点暂停、序列化状态、注入人工输入后从暂停点继续（已完成节点不重跑）。

实现（jify-engine）：
- **节点 `HumanInputNode`**（`HUMAN_INPUT`）：`data.variables` 为表单字段（`{variable,type,description,required}`）。
  首次执行若变量池没有 `nodeId.<字段>` 则返回 `NodeRunResult.paused(form)`；恢复后注入过输入则成功并把输入写为输出。
  无字段时视为「仅确认」，用 `nodeId.__approved` 哨兵判定。
- **`NodeRunResult`**：新增 `paused`（布尔）+ `pauseRequest`（表单），静态工厂 `paused(form)`、`isPaused()`。
- **`GraphRuntimeState`**：新增 `completedNodeIds` / `completedHandles`（nodeId->选中句柄，空列表=全部出边）/ `pausedNodeId` / `pendingForm`；
  新增 `snapshot()` / `fromSnapshot(Map)`（含变量池、完成状态、暂停点、元信息）；`addCompletedNode(id, handles)`。
  `VariablePool` 新增静态 `fromSnapshot(Map<String,Map<String,Object>>)`。
- **`GraphEngineEvent.GraphRunPaused`**（runId/nodeId/nodeType/title/form）新事件；`finish(WorkflowRunStatus.PAUSED)`。
- **`GraphEngine`**：executeNode 里 `result.isPaused()` → `onNodePaused`（记暂停点+发事件+finish(PAUSED)）；
  `onNodeSucceeded` 里 `state.addCompletedNode(nodeId, selectedHandles)`；
  **恢复**：`start()` 若 `completedNodeIds` 非空则进入恢复分支——用队列跳过所有已完成节点并按记录句柄重放出边，
  `skipCompletedNode` 递减 pending 并 resolveEdge；executeNode 顶部对已完成节点走同一跳过逻辑（`skippedCompleted` 原子去重，避免重复递减）。

关键坑（重要）：
1. **`ConcurrentHashMap` 不允许 null 值**：`completedHandles.put(id, null)` 会 NPE（表现为所有节点成功后 NPE → 后继不激活 → 引擎判「不可达」FAILED）。
   已改为空列表 `List.of()` 表示「全部出边」。变量池同理：节点输出为 null 时不能写入，executeNode 已跳过 null 值。
2. **恢复播种期不能做完成判定**：恢复时主线程逐个跳过已完成节点、期间工作线程可能先跑完导致 `ready` 瞬时为空 + `running` 为 0，
